Workflow map by UI mode draft

A copy of the workflow map, reworked to follow the four UI modes in REWRITE.md: Setup, Ready to cut, Job and Error. Each pill is what the UI shows, written as mode, then subheader. The steps carry the subheader shown while they run. This is a draft for discussion, and the original map is unchanged.

Open questions

  • Apply tension result: this flow only works if Apply tension always returns a result, and current Maslow-Mini does. It reaches Ready to cut, or goes back to Belts extended with an error: a belt wound in over 300 mm (probably not attached), lengths that don’t fit the anchors (20493b1b), or a position more than 25 mm off. One rare case still needs a firmware fix: if the measurements disagree nine times in a row, the state goes back to Belts extended but the board can stay in Homing. Older firmware gets stuck at Taking slack. None of this has been tested on a machine yet.
  • Automatic Park: a job success always triggers it, but who sends it? If the UI does, every connected browser could send it, and none will if no browser is open. Firmware could start it instead. It also needs to make sure the spindle is off first.
  • Saved setups: anchor points survive a restart, and Apply tension checks them. Could a user save a setup for each table and choose one, so they don’t have to recalibrate? A setup only stays valid while the anchors are in the same place.
  • Work area and anchors: the map says setting the work area clears the anchor points. No firmware code for that was found, so the rewrite would have to add it. Should it clear them, or prompt the user to recalibrate?
  • Other errors: encoder failures, a stalled update loop and startup hardware faults aren’t drawn yet. They need different instructions.
  • Skipping setup steps: keeping a saved work area skips Retract, Extend and Find anchors, but the machine can’t say whether its saved anchors were measured for this work area. The firmware, or the UI, needs to record that Find anchors finished, and for which work area.
  • New work area: does a smaller work area need a retract first? A bigger one may not, since the belt lengths are still known.
  • Reboot from the UI: FluidNC already has a restart command ([ESP444]RESTART, also $Bye). It only works while the board’s web server still answers. When the UI can’t reach the board at all, a power cycle is still the only option. Should the UI say which case it is?
  • Spindle board: if only the spindle board stops answering, does it get its own reboot?
  • Naming the device: the hotspot screen asks for a name first. It sets the hostname ($ESP112, so maslow.local becomes <name>.local) and the hotspot name ($ESP105); both default to maslow. Does the new name need a restart to take effect? Should a machine that’s already on WiFi, which never sees this screen, be able to rename itself in Device config?
  • WiFi setup dialog: it’s a placeholder (Connecting: WiFi setup) until we look at what the current dialog shows. Where does the option to turn it off live afterwards?

What’s different from the original map

  • Latest, from the layout mockups: Setup always starts with Setup: Confirm the work area. Keeping a saved work area skips straight to the tool check only if the belts are still tensioned, which can only happen after a page reload. After a reboot the encoders restore the belt lengths, but the machine never comes back tensioned, so the user always applies tension again. Otherwise the machine checks run as before, and a new work area clears the anchors, so Find anchors runs. The “Has your workspace changed?” branch from Ready to cut is gone.
  • Secure the work piece and Choose a job file are now Setup steps, so Ready to cut only shows once both are done, after Z. Jogging unlocks at the tool check, once the anchors and position are confirmed.
  • Extend now ends when the user presses Done extending, after attaching the belts to the anchors, instead of when the belts reach their full length. This needs a firmware change. Stop extending keeps the belt lengths, so the user can extend again or retract from where the belts are.
  • Tracing the boundary is optional (dashed), and sits beside Run in the UI. Error: can’t find anchors loops back to Find anchors after the user checks the belts.
  • Machine statuses are now the four UI modes, each with its own color.
  • Latest, from testing on the machine (on firmware well behind current Maslow-Mini, so to be rechecked): “Anchor points known?” and “Belts tensioned?” are gone, because the machine can’t answer them. Saved anchors always have values, and nothing records whether calibration has run. Instead, belts that are extended go to Apply tension, which checks the saved anchors, and the machine answers “Position confirmed?”.
  • If the position can’t be confirmed, the flow goes to Find anchors. The belts are already out, so no retract is needed. Older firmware can hang here instead; 20493b1b fixes it.
  • A first-time user, or someone who has moved the anchors, can go straight to Find anchors (dashed).
  • The “retract again” loops are no longer shown as unlikely. Retract can report success with belts still out if they’re under tension, so the check by eye matters, and the fix is to add slack and retract again.
  • Setup can start in Alarm after a reset, and Retract clears it. Anchor points survive a restart, so Setup doesn’t always mean recalibrating.
  • Setup needed is now Setup, and steps show their subheader, such as Setup: Retracting belts.
  • Latest: once the position is confirmed, the device checks for a tool on its own by raising the spindle through the light beam. If a bit is found, the user says whether Z is set for it; if not, they remove the bit, measure how far it sticks out of the spindle socket, enter that, and load it back in, and Z is set from the measurement. With no bit, they measure one or continue without a tool. The beam check result and setting Z from the stick-out both need firmware support.
  • The tool and Z checks are Setup steps. The UI only shows Ready to cut after them, even if the firmware already reports READY_TO_CUT, so Ready to cut now appears once, just before preparing the work piece.
  • “Secure your work piece” is now a question: Is your work piece set up and secure? The user may have calibrated with the machine on top of a large enough work piece, so they can answer yes and go straight to choosing a file.
  • “Too tight?” is no longer a question. Securing the work piece shows a suggested prompt instead: if your belts are too tight, release tension. The dashed line is that optional path.
  • Z stays before securing the work piece. It’s set from the bit’s measured stick-out, and the stock doesn’t affect it because the machine sits on top of the stock.
  • The tool check runs again after a power cycle or page load, a tool change, a user Z re-home or a spindle fault. They aren’t asked after a finished job, a stopped job or releasing tension.
  • Releasing tension to secure a work piece is shown as Setup, because that’s what the firmware does.
  • Added Choose or upload a file, now the last Setup step.
  • Added Job: Cutting. There’s no Pause: Stop is the only way to halt a job, and it should save the job’s progress so the user can continue from where it stopped. That needs a firmware change.
  • Emergency stop (by the user) is now the Stop button, which ends at Ready to cut: Job stopped and needs no power cycle.
  • Machine stopped (error) is now Error: Emergency stop. Only the emergency button or a machine error triggers it, never the UI. It needs a power cycle or $X. The bit may still be in the material, so there’s a step to check it.
  • Added Job: Spindle fault: recovering, which ends the job and re-homes Z by itself. If that fails, the UI shows Error and offers $X, then re-homing Z. This still needs testing on current firmware, with a power cycle as the fallback.
  • Success goes to Ready to cut: Parking, then Ready to cut. Power off is the option from there. Sleep has been removed.
  • Connecting is shown on Assess machine state, because the page has no state until the board answers.
  • Trace the boundary shows as Ready to cut: Moving. Jogging and manual gcode show the same subheader.
