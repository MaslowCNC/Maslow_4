Machine workflow map draft

How someone gets from power-on to a finished cut, and the machine statuses the UI shows along the way. This is a starting point for discussion: not every path is here, and the status names aren’t final.

Open questions

  • Workspace changed: retracting is needed, especially when the new workspace is smaller. If it got bigger, can we skip the retract and just extend, since the belt lengths are already known? (This is also noted on the map.)
  • Reboot from the UI: FluidNC already has a restart command ([ESP444]RESTART, also $Bye). It only works while the board’s web server still answers. When the UI can’t reach the board at all, a power cycle is still the only option. Should the UI say which case it is?
  • Spindle board: if only the spindle board stops answering, does it get its own reboot, or does a power cycle cover both boards?
  • Emergency stop: is a power cycle needed, or can the user recover from the UI?
  • Sleep: does it retract the belts?
  • WiFi setup dialog: where does the option to turn it off live afterwards?

What changed

  • “Unknown” and “Setup mode” are now one status, Setup needed. It runs the setup checks in order. Each “no” leads to the step that fixes it, then back to the next check.
  • Latest: setting the work area clears the anchor points, so after a workspace change Setup needed always recalibrates.
  • “Back online?” (after a reboot from the UI, in the Not responding path) is now a machine check. The UI can tell on its own when the board answers again.
  • A successful job now parks the machine automatically and goes straight back to Ready to cut. Sleep and power off are options from there, for when the user is done.
  • “Is your Z set?” is now “Have you set your Z?”, a question the user answers. There’s a default Z, but the user confirms it’s where they want it. A note on the map says this part may change soon.
  • A new machine check, “Belts extended?”, comes before “Anchor points known?”. If the belts aren’t extended, the user is asked “Have you set your workspace?” (the workspace sets how far the belts extend), then extends. A belt-length retract now leads straight into this check, so the extend steps appear once.
  • The workspace question is now only asked before extending, and the user answers it as “Have you set your workspace?”. Extended belts mean a workspace is already set, so calibration doesn’t check again. If the belt lengths and anchor points are already known, the machine can assume a workspace is set.
  • The checks only the machine can answer (belt lengths known, anchor points known, belts tensioned) are now blue, so they stand apart from the yellow questions the user answers. They can still prompt the user to act.
  • The “retract again” loops are greyed out as unlikely paths. Retracting again is the right fix, but a belt rarely stays out.
  • The “Error” status is now Not responding, for when the machine stops answering. The UI offers a reboot first (new, shown dashed) and falls back to a power cycle. Either way, the flow goes back to Assess machine state.
  • Calibration now comes before the tension check, because finding the anchor points also tensions the belts. “Belts tensioned?” only says no when the user has pressed Release tension, and then they apply tension before the machine is ready again.
  • After every retract, the user confirms by eye that the belts are fully in, because a belt can stay slightly pulled out. If not, they retract again. Unknown belt lengths are fixed by retracting, then extending.
  • Both routes into the tool steps first check “Tool loaded?”. If there’s no tool, the UI shows a warning and the flow carries on. Usually a tool is already in.
  • “Has your workspace changed? → yes” now retracts the belts and goes back to Setup needed, instead of repeating the setup steps on its own.
  • Grouped the steps into four stages: connect, check and set up, prepare and run, after the cut.
  • Drew machine statuses as pills so they stand apart from steps and questions.
  • Moved “Error: can’t find anchors” next to calibration, where it happens.
  • Connected the WiFi setup dialog to Assess machine state.
  • Listed the final-check items beside the Final check step.
  • Fixed spelling: “Connects”, “Retract”, “appropriate”.
